## 2. The two orders (kept separate on purpose)

1. **Execution order** — Art. 3. At runtime the *scheduler/resolver* picks rules: Aṣṭādhyāyī
   order, modified only by asiddhatva (8.2.1, 6.4.22, 6.1.86), pratiṣedha, and the Ladder-1
   conflict rules (Art. 21). No pipeline supplies order. **This is what "in the order they are
   supposed to apply" means, and it is S1's deliverable.**
2. **Authoring order** — the order in which *we* write rules: **strictly 1.1 → 8.4, pāda by
   pāda, a pāda being closed (every sūtra classified and done, §1) before the next opens.**
   One named exception: the **393 sūtras already invoked** by shipped derivations are finished
   in S1, because Gate C (autonomous loop reproduces rāma/bhū and all 364 shipped derivations)
   cannot pass with placeholders on the path. They too go in Aṣṭādhyāyī order.
   Accent (6.2, accent part of 8.1) is deferred to Track G (ROADMAP: refused until gates pass).

Testing late-pāda rules before the earlier pādas that "produce" their input is fine: the input
state is built by the existing derivations or a fixture, and the rule's `cond` reads structure,
not history (Art. 2).

- **A6**: `r1_form_identity_exempt` allowed only for ADHIKARA/ANUVADA/PARIBHASHA/pure-SAMJNA; every
  other exempt file is demoted to "registered". Ratchet = today's count, only down. Coverage

  **Every table in this plan is regenerated from it** (item 10 above).
- **Status 2026-10-03: S0 landed** — `tools/sutra_class.py` (`make confident`), `tests/constitutional/test_exempt_ratchet.py` (ceiling 3,205), `engine/coverage.py` no longer lets operational sūtras count as moved by self-exemption.

  per ROADMAP A1); bench baseline recorded (81.1 % / 338 of 417).

## 5. Risks stated plainly
- **Placeholders hide shortcuts.** Converting 6.4 may *break* forms that pipelines make by direct
  code. That is a finding, not a regression: record it as an Art. 18 gap and fix the rule.
- **Taddhita/kṛt volume (~1,550 sūtras) is the schedule.** Realistic only with a generator that
  emits per-sūtra records from the pāṭha + gaṇapāṭha with Kāśikā examples as tests, reviewed in
  batches. Without it this plan is years, not months.
- **Hours/week** (ROADMAP §7.1) remains the one input this plan cannot supply; order and gates
  are independent of it.
- **Test rationing.** 3,983 × (≥5 tests) ≈ 20,000 new tests; parametrise per pāda from cited
  tables, one `test_pada_X_Y.py` — not a file per sūtra.

## 6. Session checklist
1. `make coverage && make bench && make gaps` — record the three numbers.
2. Open `sig/sutra_class.json`; take the next unclosed pāda in order (or the S1 ledger until empty).
3. ≤1 new mechanism; if two, stop and design.
4. Per sūtra: cite text → cond (structural) → act (vocabulary op) → declare conflicts → ≥3/≥2 tests.
5. Delete pipeline code a real rule has made redundant — same commit.
6. Re-run the three numbers; none may worsen. Commit `impl(X.Y.Z): <sūtra> — <operation>`.
